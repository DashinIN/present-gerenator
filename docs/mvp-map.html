FunBaza - MVP-карта проекта

Рабочая карта текущего состояния проекта: куда движется продукт, какие пользовательские сценарии важны для MVP, как устроена информация и какие API-функции уже есть в коде.

Куда движется проект
FunBaza - web-first сервис AI-поздравлений. Пользователь в чатовой форме создает картинку и/или песню, платит кредитами, получает результат в треде и может продолжать итерации.

Что уже собрано

  • Go/Gin backend с REST API, Swagger, middleware и graceful shutdown.
  • PostgreSQL как основная база, Redis как очередь и хранилище webhook-состояния.
  • React/Vite frontend с чатовым UX, сессиями, балансом и polling статусов.
  • Worker pipeline для генерации изображений и аудио через mock или внешние API.
implemented production partial

Главный вектор MVP

  • Стабилизировать путь от запроса пользователя до результата генерации.
  • Убрать рассинхрон frontend API routes и backend /api/v1.
  • Защитить биллинг тестами: estimate, charge, refund, failed generation.
  • Подключать production-интеграции после стабилизации core flow.

Схема user stories для MVP
Основной MVP-сценарий - пользователь быстро получает персонализированное поздравление и понимает стоимость результата до отправки.

Критичные истории

  • Как пользователь, я хочу войти без сложной регистрации, чтобы быстро попробовать сервис.
  • Как пользователь, я хочу видеть стоимость до отправки, чтобы контролировать кредиты.
  • Как пользователь, я хочу видеть прогресс генерации, чтобы понимать, что задача не потерялась.
  • Как пользователь, я хочу продолжить тред, чтобы улучшать результат пошагово.

Необязательное для первой итерации

  • Telegram Mini App.
  • Полноценный платежный шлюз.
  • Социальный шаринг и публичные страницы результата.
  • Админка, модерация и A/B-тесты промптов.

Функциональная схема API
Защищенные пользовательские функции находятся под /api/v1. Auth, files и webhooks живут на отдельных public/service routes.

Функциональная схема генерации
Ключевой MVP-поток: создать задачу, списать кредиты, поставить в очередь, обработать worker-ом, сохранить файлы и вернуть результат через polling.

Что нужно делать дальше
Список сфокусирован на ближайшем MVP, а не на полной production-архитектуре.

Сначала стабилизация

  • Исправить frontend API paths: убрать двойной /api/v1 и привести lyrics к /api/v1/generations/lyrics.
  • Добавить backend-тесты на billing lifecycle и failure refund.
  • Проверить generation create/status/session polling end-to-end.
  • Зафиксировать лимиты UI и backend: сейчас backend принимает 0-1 image/song, часть docs говорит 0-3.

Потом production-ready

  • Реализовать OAuth-провайдеры вместо dev login.
  • Подключить R2 или другое S3-compatible хранилище.
  • Добавить покупку кредитов и платежные webhooks.
  • Добавить мониторинг worker-а, ошибок AI API и финансовых событий.

Критичные несоответствия текущего кода

ТемаЧто видноПочему важно
Frontend API base request() добавляет /api/v1, но часть методов передает путь уже с /api/v1. Запросы могут уходить на /api/v1/api/v1/....
Lyrics route UI вызывает /api/generations/lyrics, backend route находится под /api/v1/generations/lyrics. Генерация текста песни может не работать из интерфейса.
Docs vs backend limits Swagger/comments местами говорят 0-3, handler ограничивает 0-1. Нужно выбрать MVP-лимит и синхронизировать UI/API/docs.
Tests Выделенной тестовой базы нет. Риск регрессий в кредитах, возвратах и async worker-е.
